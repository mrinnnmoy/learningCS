# Trust Assumptions — GovernedFeeContract

## Phase 1 (as deployed in setUp — a raw EOA owner)

| Question                                             | Answer                                                                                                                                       |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Who can change the fee?                              | The single EOA at `eoaOwner` — one private key, no delay, no disclosure window                                                               |
| How fast can it change?                              | Instantly, one transaction, no advance notice to users at all                                                                                |
| What's the hard limit regardless of who controls it? | `MAX_FEE_BPS = 1000` (10%) — enforced in `setFee` itself, not dependent on WHO calls it                                                      |
| What can this owner NOT do?                          | Cannot exceed the 10% cap under any circumstance; cannot mint, pause, or touch funds — `setFee` is this contract's ENTIRE privileged surface |

## Phase 2 (after transferOwnership to a TimelockController)

| Question                                                                                                                                                        | Answer                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Who can change the fee now?                                                                                                                                     | Still, ultimately, `eoaOwner` (as the timelock's own sole proposer/executor in this test) — but ONLY via schedule-then-wait-then-execute                                                                                                                                                                                                                                                 |
| How fast can it change?                                                                                                                                         | A minimum of 2 real days between scheduling and execution — a real, guaranteed disclosure window                                                                                                                                                                                                                                                                                         |
| What changed about WHO holds power?                                                                                                                             | Nothing — same real key. What changed is HOW that power can be exercised: never instantly, always with advance, on-chain-visible notice                                                                                                                                                                                                                                                  |
| What's still true regardless of phase?                                                                                                                          | `MAX_FEE_BPS` — proven directly in `testFix_HardCapHoldsEvenThroughTheFullLegitimateTimelockFlow`                                                                                                                                                                                                                                                                                        |
| If `eoaOwner`'s single key were compromised, what could the attacker actually do, and how much advance warning would existing users have before it took effect? | The attacker could schedule valid fee changes up to `MAX_FEE_BPS = 1000` (10%) using the timelock's proposer/executor permissions, but could not change the fee instantly or exceed the hard cap. Each scheduled change must wait at least 2 real days before execution, giving existing users a guaranteed minimum 2-day, on-chain-visible warning before the change could take effect. |
